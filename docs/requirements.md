# requirements.md — i-PROカメラデータ収集・可視化PoC

## 1. 目的

i-PRO製ネットワークカメラから店舗入口のラインクロス人数およびヒートマップ情報を取得し、クラウドに蓄積してダッシュボードに表示するPoCを開発する。

表示したい情報は次のとおり。

- 各カメラのラインクロス人数（入店・退店）
- 各カメラのヒートマップ（通過量・滞留情報。利用できる種別は実機で確認）
- 現在の店内人数（対象入口の入店数 − 退店数を、基準人数から積算した推定値）
- 指定期間の来店人数（日別・時間帯別・曜日別・月別）

PoCのため、常時稼働・定期実行は必須ではない。デモ時に運用者がVPNへ接続し、手動で収集アプリを起動してデータを取得する。取得時点以降に生じた新しいデータが自動更新されるとは限らないので、表示側では最終取得日時を明示する。

- 技術検証時点はGitタグ `testing` として保存済み。タグを変更・削除しない。

## 3. 開発環境と確定方針

- 対象カメラ：2台。暫定IDは `food`、`island`。
- 接続：店舗VPN経由でカメラのプライベートIPへHTTP(S)アクセス。
- 認証：**HTTP Basic認証**。カメラ側設定は「Digest or Basic」で、Basicを利用可能。
- IPアドレス、表示名称、ユーザー名、パスワードは利用者が設定する。ソースに埋め込まない。
- 第1弾の実装言語：TypeScript。ランタイム：Node.js 22。
- 既存リポジトリはNext.js 15系、React 19系、Yarn、Biomeで構成されている。**Goal1では既存のYarn構成を維持**し、パッケージマネージャーの移行は独立した判断とする。
- UIは後続Goal4で整備。Goal1は通信検証用CLIを優先し、既存Next.js画面を壊さない。

## 4. 全体アーキテクチャ

```text
店舗内 i-PRO カメラ（2台）
    ↓ 店舗VPN・HTTP(S) CGI・Basic認証
ローカル収集アプリ（dashboard_test_for_ipro）
    ├─ ラインクロス・ヒートマップ数値 → Cloudflare D1
    └─ 明示的に取得したサムネイル → Cloudflare R2
    ↓
表示用ダッシュボード（sample_dashboard）
    └─ D1 / R2から参照・集計・可視化
```

- データ収集と表示を分離し、表示用ダッシュボードから店舗VPNへ直接接続しない。
- 通常のデータ収集では画像なしCGIを優先し、JPEG取得・R2更新は別操作にする。
- データ収集は手動実行。スケジューラーや常駐ジョブは初期要件に含めない。

## 5. データの扱い

- **ラインクロス**：カメラID、ライン番号、計測区間（開始・終了時刻）、入店・退店数を保存する。入退店の向きや集計対象ラインはカメラごとに設定可能とする。
- **ヒートマップ**：カメラID、種別（通過量・滞留）、計測区間、元グリッドを保持する。グリッド寸法や値の意味は実機データで検証する。通過量と滞留指標を同一の方法で無条件に合算しない。
- **時刻**：取得日時と計測区間を区別する。計測時刻は原則UTCで保存し、表示側でJSTへ変換。元データのタイムゾーン情報を失わない。
- **重複排除**：同一カメラ・ライン／ヒートマップ種別・計測区間の再取得で二重計上しないようにする（Goal3）。
- **現在の店内人数**：入退店差分だけでは絶対人数が保証されないため、基準日時・初期人数・欠測を考慮する。未確定なら推定値として扱う。
- **サムネイル**：R2のカメラ別キーへ明示的な操作時のみアップロード。非公開で管理し、配信・キャッシュ更新は表示側で適切に処理する。
- カメラ内の履歴保持期間は機種・アプリ・保存間隔に依存する。手動収集では取り逃しがあり得る。

## 6. 開発Goal

1. **Goal1：CGI取得検証** — 2台のカメラにBasic認証でアクセスし、ラインクロス／ヒートマップCGIのレスポンスをバイナリのままローカル保存。取得可否・エラーを記録。
2. **Goal2：TypeScript解析・正規化** — 生レスポンスをMultipart/CSV/JPEGに分離し、時刻・人数・ヒートマップを構造化。表示用リポジトリの既存パーサーは参考にする。
3. **Goal3：D1・R2永続化** — D1へのUPSERT、画像のR2保存、重複排除、再実行への対応。画像更新は通常収集から分離。
4. **Goal4：ローカル操作画面** — 収集アプリ側のNext.jsでカメラ一覧、収集ボタン、サムネイル更新、結果・エラー表示を実装。
5. **Goal5：表示ダッシュボード連携** — 別リポジトリ `sample_dashboard` をD1・R2参照へ変更し、期間別・カメラ別の表示を整える。

**依頼されたGoalだけを実装し、後続Goalの機能を前倒しで作らない。**

## 7. セキュリティ・運用の原則

- 認証情報はGit管理外の環境変数等に保存し、ブラウザへ返さない。
- Authorizationヘッダー、パスワード、認証情報を含むURLをログや例外に出さない。
- Basic認証を利用するが、HTTPでは認証情報がエンドツーエンド暗号化されない。VPNを前提とし、HTTPSが利用できる場合は優先する。TLS検証は無効化しない。
- 生レスポンス・JPEGには店舗画像等が含まれる可能性がある。ローカル保存先はGit管理外とし、公開リポジトリへコミットしない。
- カメラ設定変更や録画停止などの操作は実装しない。読み取り専用のCGIに限定する。
- 未検証の機種依存仕様を確定事項として扱わず、実機で確認した事実・未確認事項を分けて記録する。
